# 시니어독 건강백서 — 신규 글 발행 파이프라인 (클라우드 라우틴 지침)

이 파일은 매주 정기 실행되는 클라우드 에이전트가 읽고 따라야 할 표준 절차다. 에이전트는 매번 새 세션으로 시작하며 이전 실행 기억이 없으므로, 이 문서만 보고도 전체 맥락을 파악할 수 있어야 한다.

## 0. 사이트 개요
- `시니어독 건강백서` — 소형견 노령견 케어 정보 블로그. 홈페이지(`seniordog.kr`, 이 저장소, GitHub Pages)와 네이버 블로그(`blog.naver.com/seniordog_report`) 두 채널에 같은 글을 형식만 다르게 발행.
- 5개 카테고리: 건강관리(health.html), 영양·사료(nutrition.html), 용품리뷰(gear.html), 병원·비용가이드(cost.html), 집사일지(log.html).
- 수익 모델: 쿠팡파트너스 제휴 링크. 톤은 방어적 헤징 없이 직설적·단정적("~일 수도 있어요" 금지). 단, 순수 의학적 진단(예: "정확한 진단은 병원에서")은 예외 — 캐주얼하게 단정 짓지 않음.
- 이 저장소(`seniordogreport`)는 GitHub Pages로 그대로 서빙된다. **`_naver/` 폴더는 Jekyll 기본 규칙상 언더스코어 시작 폴더라 퍼블리시 안 됨** — 반드시 이 규칙 유지, `_naver` 밖으로 내부 파일을 옮기지 말 것.
- 네이버용 초안: `_naver/블로그포스팅/NN_주제명/NN_주제명.html` + `images/`
- 쿠팡 링크 메모장: `_naver/쿠팡파트너스_링크.txt`
- 이 문서를 따르는 실행은 두 가지 성격이 있다: **(a) 매주 자동 실행되는 클라우드 라우틴** — 사용자와 실시간 대화 없이 이 파일과 메모장 상태만 보고 판단. **(b) 사용자와 실시간 채팅 중인 세션** — 사용자가 채팅으로 직접 지시·상품 정보·사진을 줄 수 있다. 아래 절차 중 "라이브 채팅" 관련 항목은 (b)에서만 해당.

## 1. 매 실행 시 처리 절차 (최대 3개 글 슬롯)

이번 실행에서 최대 3개 글을 처리한다. 슬롯마다 아래 순서를 따른다:

1. `_naver/쿠팡파트너스_링크.txt`를 읽는다. `[작성 예정]` 블록 바로 위에 사용자가 채워둔 `[NN] 주제명` 섹션이 있고 상품명+쿠팡링크가 모두 채워져 있으면 → **이 슬롯은 "승인+재료 준비 완료" 상태다. 4번(콘텐츠 작성)으로 바로 진행.**
2. 그런 승인된 슬롯이 없거나 다 처리했는데 슬롯이 남았으면 → **주제 후보를 준비하고 콘텐츠 작성 없이 멈춘다** (아래 "신규 주제 준비" 참고).
3. 승인된 슬롯은 "콘텐츠 작성 및 발행"까지 전부 수행.

이번 실행에서 실제로 발행한 글, 준비만 해둔 주제 후보를 마지막에 정리해서 커밋 메시지와 최종 요약에 남긴다.

## 2. 신규 주제 준비 (주제가 아직 없을 때)

- 5개 카테고리 중 **글이 가장 적은 카테고리**를 확인 (홈페이지 각 카테고리 페이지의 글 목록으로 판단).
- 그 카테고리에 맞는 주제 후보 3~4개를 만든다. **절대 혼자 하나로 확정하지 않는다** — 후보만 준비.
- 후보 승인 방법은 두 가지다: **① 라이브 채팅** — 사용자가 대화 중 후보 하나를 고르면 그 세션에서 바로 `[NN] 주제명`으로 확정해 메모장에 반영(3번 섹션 참고), 상품 정보도 이어서 채팅으로 받는다. **② 파일 직접 편집** — 사용자가 다음 자동 실행 전에 직접 저장소에서 `_naver/쿠팡파트너스_링크.txt`의 `[작성 예정]` 섹션을 `[NN] 주제명`으로 바꿔써도 동일하게 승인으로 인정한다. 에이전트는 후보를 그 파일에 "제안" 형태로 남겨두면 된다(둘 중 어느 방법으로도 확정 가능하게).
- 주제가 정해지면(라이브 채팅으로 확정했거나, 다음 자동 실행 전에 파일이 실제 `[NN] 주제명`으로 바뀌어 있으면) 그 즉시 원자적으로 처리할 것 (아래):
  1. `_naver/블로그포스팅/NN_주제명/images/` 폴더 생성
  2. `posts/images/NN/` 폴더 생성 (홈페이지용)
  3. `_naver/쿠팡파트너스_링크.txt`에 `[NN] 주제명` 섹션 추가 — 상품 슬롯 2개, 각각 **정확한 쿠팡 검색어**(그대로 붙여넣기 가능한 문자열 + "판매량순" 정렬 지시) 힌트 포함
  4. 상품명/링크가 비어있으면 **여기서 멈춘다** — 리서치도 글쓰기도 하지 않는다. 라이브 채팅 세션이면 사용자에게 바로 요청(3번 섹션 참고), 자동 실행이면 다음 실행 때 다시 확인.

## 3. 라이브 채팅에서 쿠팡 상품 정보 받기 (실시간 대화 세션 전용)

사용자는 더 이상 `_naver/쿠팡파트너스_링크.txt`를 직접 열어 편집하지 않아도 된다 — 채팅으로 상품명(또는 그냥 사진) + 쿠팡파트너스 링크를 던져주면, 그 자리에서 에이전트가 처리한다:

1. 어느 `[NN] 주제명` 슬롯의 상품인지, 상품 1/2 중 어느 자리인지 확인(애매하면 사용자에게 묻는다).
2. 사용자가 채팅에 이미지를 첨부했으면 파일로 저장해 `posts/images/NN/`와 `_naver/블로그포스팅/NN_.../images/` 두 폴더 모두에 배치. 파일명은 기존 관례(`NN_상품_설명.png/jpg`)를 따른다.
3. `_naver/쿠팡파트너스_링크.txt`의 해당 섹션에 상품명·쿠팡파트너스 링크(가격은 사용자가 준 경우만)를 채우고, 이미지가 있었으면 `이미지 파일: 파일명 (반영 완료)` 줄을 추가, 상태 줄을 갱신한다.
4. 그 자리에서 바로 `git add -A && git commit && git push`로 반영한다 — 다음 자동 실행이 파일만 보고도 "승인+재료 준비 완료" 상태를 인식하게.
5. 상품 2개 다 채워졌으면(=슬롯이 "콘텐츠 작성 및 발행" 조건을 만족하면) 바로 이어서 4번 섹션(콘텐츠 작성 및 발행)을 진행해도 되고, 사용자가 "나중에 자동 실행 때 해줘"라고 하면 여기서 멈춰도 된다 — 사용자 의사를 따른다.

## 4. 콘텐츠 작성 및 발행 (상품명+링크까지 채워진 슬롯만 해당)

1. **리서치**: WebSearch로 실제 수의학/영양학 근거 자료를 찾는다. 추측으로 채우지 않는다.
2. **톤**: 방어적 헤징 금지, 가격·추천은 직접적으로. 의학적 진단만 예외.
3. **홈페이지용 HTML** (`posts/NN-주제명.html`): 기존 발행된 글(`posts/01~05-*.html`)의 구조를 그대로 따른다 — meta/OG/JSON-LD, `.summary-box`, `.toc-box`, `.product-card`(구체적 상품명이 링크 텍스트, `.name`엔 일반 카테고리명), `.affiliate-disclosure`, FAQ, 태그.
4. **네이버용 HTML** (`_naver/블로그포스팅/NN_.../NN_....html`): 기존 발행 파일들을 템플릿으로 삼되 다음 제약을 지킬 것 —
   - `<style>` 태그는 네이버 에디터가 무시하므로 인라인 스타일/명시적 `<br>`로 줄간격 확보
   - `<ul>/<li>` 금지 — `&middot;` + `<br><br>`
   - FAQ Q/A 사이, h3+p 블록 사이 빈 줄 명시적으로 추가
   - 쿠팡 상품 이미지는 `<img>` 태그로 절대 넣지 않음 — `.photo-slot` 텍스트 안내로 대체("📷 이미지 확보 완료: 파일명 — 직접 업로드해주세요")
   - 상품 링크 텍스트는 구체적 상품명 (일반 라벨 "쿠팡에서 보기" 금지)
5. **표(table)마다 대응 인포그래픽**: 글에 표로 정리한 핵심 데이터(비교표, 비용표, 단계별 대처법 등)는 각각 SVG로 그려서 `scripts/`에서 sharp로 PNG 렌더링(density 300 이상) 후 두 이미지 폴더(`posts/images/NN/`, `_naver/블로그포스팅/NN_.../images/`)에 배치. **표가 여러 개면 인포그래픽도 그만큼.** 브랜드 팔레트 고정: `--paper:#F3EEE1, --pine:#2F4C3E, --pine-strong:#1F332A, --brass:#9C7A2E, --brass-bright:#B5924A, --rule:#CDC2A2`.
   - **공장형 금지** — 이전 글들과 다른 시각 형식을 매번 사용할 것(도넛 진행형, 신호등 단계형, 숫자 카드형, 아이콘 그리드형 등 다양화). 직전 몇 개 글의 `posts/images/`를 확인해서 반복되는 형식 피할 것.
6. **라이프스타일 사진**: Pexels에서 2장 내외. 검색어는 "[견종/체구] + [글의 구체적 상황]" 조합 (예: "small dog eating bowl", "small dog vet checkup") — "dog" 같은 두루뭉술한 키워드 금지. Pexels는 출처 표시 의무 없음 — 발행 페이지에 크레딧 문구 달지 않음.
7. **상품 이미지**: `_naver/쿠팡파트너스_링크.txt`에 상품 사진 파일이 언급되어 있으면(3번 섹션의 라이브 채팅 절차나 사용자가 미리 넣어둔 경우) 그걸 두 이미지 폴더 모두에 반영. 없으면 홈페이지는 `.thumb` placeholder("상품 이미지 준비 중")로 둔다.
8. **직전 글의 "다음 글" 갱신**: 새 글을 발행하면, 바로 이전 번호 글의 "다음 글" 섹션을 열어 실제 새 글 제목/링크로 갱신한다(홈페이지는 실제 파일 링크, 네이버는 텍스트만이라도 정확히). **새 글 자신의 "다음 글"에는 미확정 미래 주제를 예고하지 않는다** — "다음 글은 준비되는 대로 올라와요" 같은 중립적 문구만 사용.
9. **목록 갱신**: 해당 카테고리 페이지, `index.html`의 POSTS 목록, `sitemap.xml`에 새 글 추가.
10. **제목 SEO**: `<title>`/`h1`에 "강아지" 등 실제 검색어를 자연스럽게 포함 (키워드 스터핑은 하지 말 것).
11. **채팅에서 바로 볼 수 있는 링크 제공**: 발행이 끝나면 두 글 모두 채팅(세션 최종 출력/요약)에 클릭 가능한 링크로 남긴다.
    - 홈페이지용 글: `https://seniordog.kr/posts/NN-주제명.html` (커스텀 도메인 라이브 링크. `git push` 후 GitHub Pages 배포에 수 분 걸릴 수 있다고 한 줄 안내).
    - 네이버 초안 HTML: `_naver/` 폴더는 퍼블리시되지 않아 라이브 URL이 없으므로, `Artifact` 도구로 해당 HTML 파일을 그대로 퍼블리시해 미리보기 링크를 만들어 제공한다(파일 경로: `_naver/블로그포스팅/NN_.../NN_....html`).

## 5. 완료 후

- `git add -A && git commit` (커밋 메시지는 한국어, 존댓말 아님 — 기술적 요약체 괜찮음) `&& git push`.
- 이번 실행에서 발행한 글, 준비만 하고 멈춘 슬롯, 다음 실행 전에 사용자가 해줘야 할 일(상품 정보는 이제 파일 편집이 아니라 채팅으로 알려주면 됨 — 3번 섹션)을 명확히 요약해서 세션 마지막 출력에 남길 것. 발행한 글이 있으면 4-11번의 링크(홈페이지 라이브 URL + 네이버 초안 Artifact 링크)도 반드시 포함.

## 6. 기술 환경 참고
- 인포그래픽 렌더링(SVG→PNG)에는 `sharp` 패키지가 필요하다. 이 저장소엔 포함돼 있지 않으므로, 매 실행 시작 시 임시 작업 디렉토리(예: `/tmp/render/`)를 만들고 `npm install sharp`부터 실행할 것.
- 렌더링한 SVG/스크립트 파일은 작업 완료 후 저장소 밖(임시 디렉토리)에만 남기고, 최종 PNG만 이미지 폴더에 커밋할 것 — `.svg`나 렌더링용 `.js` 스크립트를 저장소에 커밋하지 않는다.

## 7. 절대 하지 않는 것
- 주제를 후보 없이 혼자 확정
- 상품명/링크가 비어있는데 글 작성 진행
- 쿠팡 상품 이미지를 네이버 HTML에 `<img>`로 삽입
- 표를 만들어놓고 대응 인포그래픽 생략
- 로고/브랜드 아이덴티티(파비콘, 헤더 로고 등) 임의 변경 — 이건 이 파이프라인 범위 밖, 손대지 말 것
